# صف کشف ادعاهای کارنامه — فاز نخست

این سامانه یک **موتور کشف نامزد ادعا برای بازبینی تحریریه** است. خروجی آن فهرست ادعاهای منتشرشده یا حقایقِ بررسی‌شده نیست و **هیچ مدخلی از آن خودکار به `/karname/`، `karname/daftar.md`، پروفایل چهره یا نمرهٔ فرد اضافه نمی‌شود.**

## منابع واقعی پندار

- `backend/data/editorial-recaps.json`: ری‌کپ‌های موضوع‌بندی‌شدهٔ چهره‌ها؛ عبارت استخراج‌شده متن **ری‌کپ تحریریه** است، نه لزوماً نقل‌قول لفظ‌به‌لفظ از ویدئو.
- `web-static/data/pendar-editorial-views.json`: بخش `quote_fa` نقل‌قول‌های ویرایش‌شده؛ بدون لینک ویدئو، زمان بیان و اصالت متن هنوز در سطحِ سند اصلی تأیید نشده است.
- مرجع هویت: `backend/app/figures.py`، با نام و نام‌های جایگزین. دادهٔ دارای چند گوینده به اولین فرد نسبت داده نمی‌شود.
- بانک کارنامهٔ فعلی: `backend/data/karname.json` فقط برای نشان‌دادن **شباهت احتمالی** و جلوگیری از بازنویسی عجولانهٔ مدخل‌های اصلی خوانده می‌شود.
- نسخهٔ مستقل جان‌کلام از داده‌های پندار استفاده می‌کند؛ برای جلوگیری از دوباره‌شماری، فعلاً جداگانه وارد نمی‌شود.

## اجرای دستی و خودکار

```bash
python -m unittest discover -s backend/tests -p 'test_karname_candidates.py' -v
python backend/scripts/collect_karname_candidates.py
python backend/scripts/collect_karname_candidates.py --check
```

خروجیِ خصوصی از نظر **مسیر انتشار سایت**: `backend/data/karname-candidates.json` (در `web-static/data` یا `site/data` کپی نمی‌شود). توجه: این فایل پس از کامیت در مخزن عمومی GitHub قابل مشاهده است؛ منابع ورودی از داده‌های موجود و از پیش منتشرشدهٔ پندار هستند.

گردش‌کار `.github/workflows/karname-intake.yml` هر **شش ساعت**، هنگام تغییر فایل‌های ورودی و به‌صورت دستی اجرا می‌شود. برای هر اجرا ابتدا آزمون‌ها اجرا می‌شوند، سپس خروجی به‌عنوان artifact ذخیره می‌شود و فقط اگر صف تفاوت داشته باشد، خودکار در مخزن ثبت می‌شود. اجرای تکراری بدون تغییر، کامیت جدید ایجاد نمی‌کند.

اگر GitHub Actions مجوز نوشتن روی شاخهٔ اصلی نداشته باشد، artifact برای بازبینی در همان اجرا باقی می‌ماند ولی به‌روزرسانی خودکار فایل مخزن نیازمند اصلاح مجوزها است.

## هر مدخل چه دارد؟

- شناسهٔ پایدار `KC-...` از متن + گوینده؛ منبع‌های متعددِ یک عبارت یکجا جمع می‌شوند.
- `speaker_handle`، `speaker_name` و `identity_status`. `speaker_handle=null` برای موارد مبهم یا میزگرد.
- `excerpt_exact_from_field` دقیقاً بخشی از **فیلد مبنا** است؛ خلاصهٔ ری‌کپ را با گفتار اصلی اشتباه نگیرید.
- `origins`: شناسهٔ سند، فیلد، نام منبع، پیوند HTTPS معتبر (اگر موجود باشد)، تاریخ و هش محتوای مأخذ.
- `trigger_hint`: نشانهٔ شرط/زمان به‌صورت عبارت خام؛ `verified_due_at` عمداً `null` است تا تاریخ شمسی، «ماه آینده» یا یک روز گزارش را به اشتباه موعد تلقی نکنیم.
- `related_ledger_claim_ids_for_review`: صرفاً موارد مشابهی که باید بررسی شوند؛ ادغام خودکار معنایی انجام نمی‌شود.
- `status=pending_editorial_review` و `editorial_decision=null` در ابتدا. تصمیم‌ها در اجرای بعدی حفظ می‌شوند.

## قواعد انتشار

۱. بررسی انتساب، متن کامل، تاریخ بیان و نسخهٔ اولیهٔ منبع.
۲. تعیین اینکه جمله پیش‌بینی، وعده، سناریوی مشروط، نقل گزارش یا توصیه است.
۳. در موارد آینده‌نگر، تعیین رویداد سنجش، شرط، موعد دقیق یا اعلام «بدون موعد قابل اندازه‌گیری».
۴. کنترل تکراری نبودن با متن اصلی و ادعاهای موجود؛ به‌ویژه جملات مشترک منبع چندرسانه‌ای.
۵. تنها پس از تأیید سردبیری، ورود **مستند و مستقل** به دفتر `karname/daftar.md` در یک تغییر بازبینی‌شده؛ تولید نمره نیازمند پروندهٔ مستند نتیجه است.

## محدودیت‌های نسخهٔ اول

این استخراج‌گر «قانون‌محور» و محتاط است: ممکن است بعضی ادعاها، به‌ویژه کنایه‌ها و سخنان پیچیده، را پیدا نکند یا برخی تحلیل‌های غیرقابل‌سنجش را به صف بیاورد. صف برای **بازبینی** است؛ نه انتشار و نه آمار موفقیت. اتصالِ منبع مستقل دیگر، تحلیل معنایی دقیق‌تر و نظام تصویب/رد، مراحل جداگانهٔ آینده‌اند.
